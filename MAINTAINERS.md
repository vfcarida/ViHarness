# Maintainers

This document lists the current maintainers of Vi-Harness and their areas of responsibility.

| Maintainer | GitHub | Area of Responsibility |
|---|---|---|
| Vi-Harness Contributors | [@vfcarida](https://github.com/vfcarida) | Core runtime, security, context compaction, MCP/ACP protocols |

## Response Time Service-Level Objectives (SLOs)

| Interaction Type | Target Response Time |
|---|---|
| Security vulnerability reports | Within 3 business days (acknowledgement) |
| Bug reports (Critical) | Within 7 business days |
| Bug reports (Non-critical) | Within 14 business days |
| Feature requests / discussions | Best effort; community input is welcome |
| Pull request reviews | Within 14 business days |

## Governance

Vi-Harness follows a **Benevolent Dictator for Now (BDFN)** model while the project is in its early `0.x` phase. Governance will evolve toward a more formal RFC process at `v1.0`.

See [GOVERNANCE.md](GOVERNANCE.md) for the full governance policy.

## Becoming a Maintainer

Consistent high-quality contributions to `src/core/`, `src/infra/`, or the test suite may lead to a maintainer invitation. There is no formal application process — maintainers are nominated by existing maintainers based on demonstrated track record and alignment with project values.

## Contact

For security issues, use the [GitHub Security Advisory](https://github.com/vfcarida/Vi-Harness/security/advisories/new) — do not open a public issue.

For general questions, use [GitHub Discussions](https://github.com/vfcarida/Vi-Harness/discussions).
